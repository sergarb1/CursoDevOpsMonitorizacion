⚠️ CSRF: Jenkins exige un crumb para peticiones POST. Se obtiene con curl .../crumbIssuer/api/json y se envía en el header Jenkins-Crumb: <token>.

🧩 Conceptos Jenkins

Pipeline Declarativo: estructura rígida con pipeline, stages, steps. Más legible y mantenible.
Pipeline Scripted: Groovy puro, más flexible pero más complejo.
Job / Build: job = tarea configurada; build = ejecución concreta de un job.
Trigger: polling SCM (H/2 * * * *), webhooks, o disparo manual.
Agent: dónde se ejecuta el pipeline (agent any, agent docker, agent none).

🔌 Plugins vitales

Git: clonar repositorios.
Docker Workflow: construir imágenes.
Credentials Binding: inyectar secretos.
Prometheus: exponer métricas.
Blue Ocean: UI moderna de pipelines.

🏗️ Tipos de jobs

Freestyle: interfaz web, scripts sueltos.
Pipeline: Jenkinsfile (recomendado).
Multibranch: un pipeline por rama.

📄 Jenkinsfile declarativo

pipeline {
    agent any
    environment { APP_NAME = "miapp" }
    stages {
        stage('Checkout') { steps { checkout scm } }
        stage('Build')    { steps { sh 'npm ci' } }
        stage('Test')     { steps { sh 'npm test' } }
        stage('Package')  { steps { sh "docker build -t ${APP_NAME}:${BUILD_ID} ." } }
        stage('Deploy Staging') {
            steps { sh "docker run -d --name ${APP_NAME}-staging ${APP_NAME}:${BUILD_ID}" }
        }
        stage('Smoke Test') {
            steps {
                sleep 10
                sh "curl -s http://staging:3000/health | grep healthy"
            }
        }
        stage('Approval') {
            steps { input message: '¿Desplegar a producción?', ok: 'Desplegar' }
        }
        stage('Deploy Production') {
            steps { sh "docker run -d --name ${APP_NAME}-prod ${APP_NAME}:${BUILD_ID}" }
        }
    }
    post {
        success { echo '✅ Pipeline completado' }
        failure { echo '❌ Pipeline fallido' }
    }
}
💡 Notas: BUILD_ID = número único del build (mejor que latest). sleep da tiempo a arrancar antes del smoke test. input detiene el pipeline hasta que un humano pulsa "Desplegar" (Continuous Delivery).

📘 Conceptos DevOps

CI: Integrar cambios a menudo + pruebas automáticas.
CD (Delivery): App lista para desplegar; producción requiere aprobación manual.
CD (Deployment): Despliegue a producción totalmente automático.
IaC: Infraestructura como Código (Terraform, CloudFormation).
Observabilidad: Métricas (Prometheus) + Logs (Loki/ELK) + Trazas (Jaeger).
Rollback: Volver a versión estable anterior de forma inmediata.
Artefacto: Producto del pipeline (imagen Docker, JAR, WAR, binario).

✅ Buenas prácticas

✔️ Pipeline como código (Jenkinsfile en Git).
✔️ Imagen inmutable: misma de staging a producción.
✔️ No usar :latest; etiquetar con BUILD_ID o hash del commit.
✔️ Credenciales en Jenkins (Credentials Binding), nunca en código.
✔️ Idempotencia: Terraform y pipelines repetibles sin efectos laterales.
✔️ Separación de entornos (redes, variables de entorno).
✔️ Limpieza periódica: docker system prune -f.
